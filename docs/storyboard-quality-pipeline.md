# 分镜生成质量改造（2026-10-30）

本轮保留导演 Agent、语义槽位和 FL2VA/Ref2VA 决策。后端校验输入，编译并执行导演或用户的方案，不根据人数自行切换模式或删减素材。

## 节奏与提示词

- H3 每次生成仍限定为 **4～8 整数秒**。镜内段可以是整个连续镜头，也可以是多个正整数秒段；总和必须精确等于外层时长。
- 删除固定机位比例门禁，以及强制每 1～2 秒切镜的提示和 schema 限制。保留人物朝向、视线、注意对象和事件反应的规划要求；安静倾听和保持状态是合法动作。
- 已有导演首尾帧槽位直接通过共享渲染器编译，不再调用第二个文本模型改写。帧编辑器保存用户正文，执行时附加一次有序素材说明和当前服装信息。
- 静态图编译器保留显式构图、人物和摄影字段，不根据关键词补造镜头焦距、光影、姿势或环境。
- H3 区分初始人物状态和镜内动作。删除强制全员不断做手势、移动的执行提示；保留完整台词、声音引用、跨切镜语句标记和收尾预算。
- 用户请求的关键帧推演、四/九宫格等独立创作功能继续存在。本轮跳过的是已有首尾帧规划的重复改写，不把未规划的中间画面伪装成确定性投影。

## 参考素材

结构化分镜使用明确的画内人物、场景、道具和指定参考。缺失人物图片、缺失道具记录、超容量或人物引用冲突直接报错，不继续提交缩减版人物清单。

ComfyUI Qwen 图片接口逐张读取并上传参考图。任一读取或上传失败都停止本次提交，避免“缺一张参考图仍然生成”。结构化图片请求保留用户负面提示词，不再自动叠加大段禁站姿、禁构图模板。

## 本次实际输入

每个分镜的「生成记录·实际输入」可按图片/视频、生成记录和提交次数查看：

- 提交时的分镜内容摘要、版本号（源记录有提供时）与时间；
- 最终正文、实际负面提示词、提交参数；
- 有序参考素材、人物标识、内容 SHA256；
- 排除凭据和媒体二进制后的请求记录。

图片快照在 ComfyUI `/prompt` 提交前保存，包含工作流的实际种子、采样器、步数和对齐后的尺寸。H3 快照在视频桥接 API POST 前保存，记录桥接请求；桥接服务成功提交后回传实际模型文件、编码器、VAE、采样器、种子、步数、生成帧数与输出帧数，追加到该次快照的 `execution`。例如 6 秒输出为 144 帧，H3 实际生成 158 帧后裁剪，二者分别记录。若旧桥接接口未回传执行参数，随机种子保留 `upstream_selected`，不捏造未知值。远端 URL 的字节内容未获取时，其内容摘要明确为空，不能当成内容哈希。

快照保存在 `image_generations.input_snapshot` / `video_generations.input_snapshot`，同一生成记录的多次提交追加保存。仅详情接口返回完整快照，列表轮询不返回大正文。旧记录、上传记录及未到提交边界的失败不回填历史快照。

## 验证与样片

后端回归覆盖连续固定镜头、整秒时长约束、静态定格直出、人工正文保留、缺失素材阻断、Comfy 实际提交、H3 实际提交和快照脱敏；同时保留台词、模式、首尾帧策略等现有测试。

固定样例在 `backend-node/test/fixtures/qualityShots.js`：单人对白、双人对视、事件触发反应、连续动作。离线导出输入：

```bash
node scripts/quality_prompt_comparison.js <改动前仓库副本> <独立输出目录>
```

H3 对照分为改动前、仅放宽节奏、简化提示词三个阶段。所有阶段使用相同素材、种子、1344×768、6 秒、23 步；图片编译器前后对照使用相同素材、种子和 20 步。保留请求、工作流、失败记录、输出及耗时。固定种子的小样仅用于检查退化，不能证明所有场景质量提高；此实验也不衡量被移除的随机文本润色服务。

不安装 ASR，不将 TTS 强行替换 H3 成片音轨，不自动重跑已有剧集。语音是否完整、口型及人物反应仍需以样片验收。

### 本轮验证结果

- 后端 447 项、前端 82 项、桥接 18 项测试通过；前端生产构建通过。
- 完成 8 张对照图片和 10 条对照视频。单人对白、事件反应做三阶段视频对照；双人对视、连续动作做前后两阶段，两个可选中间阶段在报告中明确标为未执行。10 条视频均验证为 1344×768、24fps、6 秒。
- 抽样观察中，简化版本更好地保留躺卧姿态，放碗动作从重复执行改善为一次连续动作；双人画面的开场裁脸、手部接触位置偏差和未规划运镜仍存在。静态图并非都比旧版更好，不能据此承诺全面免返工。
- 模型执行约 9.7～10.7 分钟，本轮未观察到明显速度提升。没有完成音频内容核听，不能认定缺字或无台词镜头的幻觉语音已解决。

样片、工作流、请求和失败记录发布在 [局域网对照页](http://10.10.13.15:5679/static/quality-validation/20261030/report.html)。这些是独立测试产物，没有覆盖已有剧集数据。

### 对白与动作脱节修复

### H3 Motion Context 参考

对照 `ComfyUI-H3-Motion-Context` 后确认，它解决的是另一层问题：把上一条 H3 的 **视频/音频 latent** 保存下来，在下一条生成时将上一条尾部的 latent 作为上下文，并在交付前裁掉被固定的头部。这样可以避免每一镜只拿一张解码后的尾帧图片重新编码造成的接缝、颜色漂移和声音重启。它要求相邻片段分辨率一致，并按 H3 的 24fps 帧网格（`17k+5`）处理长度。

当前 LocalMiniDrama 的长镜头接力已经做到：由导演 Agent 声明 `long_take_group_id/sequence`，等待前段视频完成，提取真实尾帧作为后段 FL2VA 首帧；它还没有接入该插件的 latent 保存、音频 latent 延续和 Trim 流程。因此不能把这个插件的“latent 无损接力”描述成系统现有能力。后续若接入，应把它作为 H3 执行层能力，仅用于明确声明的 `long_take_continuation`，不能让执行器替导演 Agent 选择接力镜头。

用户回放指出双人样片在“爹，我扶您起来”结束后继续躺卧。复查发现测试输入给双方的轨迹均为“保持姿态安静倾听”，父亲终态仍为半躺；因此此前的“躺卧姿态保持”观察不能作为这个剧情事件完成的证据。

- 导演初稿、人物定格、视频槽位、时间线规划、门禁修复和单镜微调共用对白与动作完成要求：区分当场意图、未来承诺和受阻情形，在现有动作、结果和终态字段内规划配合与反应，并在输出前自检语义一致性。这是 Agent 的语义判断要求，不是关键词硬门禁，也没有新增一轮模型调用。
- H3 编译器删除“说完后安定下来”“收尾闭嘴静止”“持续保持终态”等通用停顿指令。保留语音截止时间，结束发声后继续已规划动作；旁白也不要求画内人物停下动作。编译版本更新为 `h3-native-v14-speech-independent-actions`，避免命中旧提示词缓存。
- 导演修复提示中残留的强制动态运镜指令已删除。安静倾听、固定机位仍然合法，不按台词关键词补造动作。
- 双人回归样例修正为同一连续镜头：0～3秒说话并托肩背，3～5秒配合扶起，5～6秒坐稳并保持支撑；结束定格同步为坐姿。旧对照输入和成片保留，新增样片单独存放。
- 新增回归覆盖“3秒说完、6秒完成动作”、旁白与无时间线编译路径、未来承诺不触发后端编造动作。修复后后端共450项通过。

已有分镜的错误动作规划不会被执行层偷偷改写。需通过单镜导演微调更新动作过程和终态，再生成视频；不需要重跑整集。代码测试只能验证规划要求和编译行为，实际扶起效果仍需检查新样片。

额外使用线上 `gpt-5.6-sol` 调用现有视频槽位规划节点，在只提供剧情目标与初始姿态、未提供人工轨迹的情况下，单次输出已包含女儿托肩背、父亲撑床配合、坐稳的过程，并明确对白后继续动作。该验证只读取线上 AI 配置，结果保存在独立测试目录，不写入剧集；它不是整集生成质量评测。固定回归视频与这次独立导演输出可在 [动作完成复测页](http://10.10.13.15:5679/static/quality-validation/20261030-action-completion/report.html) 分别查看。

新6秒样片已完成。每0.5秒抽帧可见父亲由半躺到坐起，女儿持续扶持，结束时两人坐稳并交流视线，本条“扶起事件”画面验收通过。实际动作较规划提前完成，手部接触也非逐字精确，不能据此承诺精确时序或所有双人场景都成功。音频未听辨验收。样片实际工作流相较旧双人简化版仅提示词和输出文件名改变，保持相同素材、种子、GPU及采样参数。
